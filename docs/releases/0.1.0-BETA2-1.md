# DeepSeek Harness Code 0.1.0-BETA2-1

> 这是社区发行版，不是 DeepSeek 官方产品。`v0.1.0-BETA2-1` 源码标记指向 `bb89b52176ae3d3c67185331a029c04d0dd35f58`，GitHub Release/资产均存在；在 BETA2-2 成功发布前，它仍是 Latest/non-prerelease。最终 package/publish Run [32389858728](https://github.com/Code-DSH/deepseek-harness-code/actions/runs/32389858728) 全绿，不能把本版本的退役原因改写成“最终 CI 失败”。

## 产品修复

- 使用唯一的 `__DSH_PERSISTENT_BASH_PROMPT__`，并按实际 prompt 长度计算尾部边界，修复 persistent Bash PTY readiness 卡死。补丁通过 `config/node-runtime` 与打包运行时 lockfile 可复现地交付。
- 提供用户确认的更新下载、架构匹配、SHA-256 校验、平台替换与重启；没有静默后台替换。
- 发布架构感知的 `update-manifest.json`，覆盖 Universal macOS、Windows x64/arm64、Linux x64/arm64 资产。
- 在继续要求 HTTPS、逐跳重验、拒绝私网/loopback 的前提下，允许 GitHub 签名资产跳转主机 `release-assets.githubusercontent.com`。
- 大文件使用可恢复的 32 MiB Range 分块，每块带重试和尺寸校验。
- 本机从远端更新并重启后，原先 300 秒超时的同形 Bash 调用返回 `BASH_PATCH_OK`；这是已记录的产品验证，不是对所有平台安装路径的替代证明。

## 为什么不再适合作为当前下载入口

- **fresh-install 插件协调**：BETA2-1 对每个托管插件各执行一次同步 official plugin CLI。其最终发布 roster 当时通过 CI，但该串行路径在 Windows 已接近时限；扩展到 BETA2-2 roster 后会到达 600 秒失败。BETA2-2 候选修复把完整 roster 合并为每次尝试一次无 shell 的官方 CLI 调用，并要求安装后原生启动证据。
- **Node 前置条件文案不一致**：实际代码始终要求系统安装的官方 Node.js >=22.13，并不会自动安装 Node。[Issue #17](https://github.com/Code-DSH/deepseek-harness-code/issues/17) 的维护者回复曾错误声称一键安装器会自动安装；没有 Node 的机器在按官方链接完成安装前无法启动 Harness。
- 因此，退役对象是“不可靠且前置条件表达错误的安装/首次启动入口”，不是证明每个 BETA2-1 资产必然失败，也不是改写其绿色 CI 历史。

## 更新与保留边界

使用“设置 → 通用 → 检查更新”。发现新版本后，只有选择“更新并重启”才会下载并校验当前平台包，再退出并交给替换助手。应用必须位于持久路径；DMG 挂载路径与 Gatekeeper translocation 路径会被拒绝。

只有在 BETA2-2 成为 Latest，且资产与 `update-manifest.json` 已独立验证后，才删除 BETA2-1 的 GitHub Release/资产。保留 `v0.1.0-BETA2-1` 源码标记与本归档文档，用于审计和恢复；当前不得提前写成“已删除”。

macOS 包仍为 ad-hoc 签名且未经过 Apple 公证。请参阅[未签名安装说明](../operations/install-unsigned.md)，只清除本应用的 quarantine。

## English summary

BETA2-1's final publish run was green. It fixed persistent Bash readiness and shipped a user-confirmed, SHA-256-verified update path. It is being replaced because synchronous per-plugin first-install reconciliation and inconsistent Node prerequisite messaging made the fresh-install path unreliable—not because every asset failed. The GitHub Release/assets are deleted only after BETA2-2 is Latest and independently verified; the source tag and this audit record remain.
